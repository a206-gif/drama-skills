# Agent Note: 漫画信息表达、详细文字与跨话事件承接

Status: implemented

## Problem

创作者要求画面准确表达信息、对白和旁白具体明确、内容细致，并禁止上一话正在讲的事在下一话无交代地消失。既有[静态漫画](../../implemented/feature/2026-10-24-static-comic.md)与[原著推广](../../implemented/feature/2026-10-24-static-comic-novel-promotion.md)决定提供了分页排字和推广目标，但未要求逐格的信息/衔接说明，也没有可执行的相邻话待续事件对账。推广选段不能被当成跳过正在推进事件的许可。

## Decision

- 将信息准确、文字足够明确与连载承接设为硬性结构/语义义务，优先于固定页数、格数、短句和推文的快节奏；必要时增加格页，不省略关键因果或用抽象旁白冒充过程。
- 分镜每格补非空“信息”“衔接”，对白明确对话对象、旁白明确叙述身份，继续只在 Markdown 维护实际正文；排版 JSON 不新增剧情副本。
- 在同一分镜页前增加本话编号、连载关系、上话编号、入口/出口状态与承接/待续事件。事件使用稳定 ID、状态、当前格/文字落点及具体事实，不建并行连续性数据库。
- 工具对首话/续话/明确批准的独立篇作区分；续话 `check`/`render` 需要显式 `--previous` 上话分镜，核对相邻话号、全部上话待续 ID、有效落点、继续/暂缓事件不得丢失、已解决事件不得同时待续。只核对相邻一对，不宣称已审查全书或整条连载。
- 真正解决、推进、明确暂缓的因果与读者可见性仍由引用原著和当前分镜/实际图片的语义自检判定；伪写状态、只在制作备注解释、擅自改成独立篇绕过待续都不能交付为完成。
- 补成对的合成示例、详细图文参考和行为回归，保留原著推广、搜书提示、无自动付费/上传和单一正文边界。

## Alternatives considered

- **只加“保持连贯”的文案**：最少侵入，也不增加格式。未采用：它不能显式追踪上一话尚未处理的事，正是创作者指出的失效方式。
- **让校验器通过对白或图片语义自动判定事件已解决**：可以减少制作记录。未采用：本地确定性工具没有这种能力，不能把字符串匹配或 ID 存在当成剧情通顺的证明。
- **新增故事状态 JSON/独立承接台账**：跨话检索更方便。未采用：容易与分镜演变成两份故事真相；把最小交接写在当前分镜里，并让事件引用实际格/文字。
- **保持“越短越好”，以剧情摘要接下话**：符合部分推文节奏。未采用：用户明确禁止无交代跳过事件；长短和版式必须让位于表达与承接，而非相反。

## Consequences

- 收益：每格的读者信息与前后关系明确，待续事件不再能在交接记录里静默消失；对白、旁白和实际输出有明确核对点。
- 代价：新分镜要求补齐头部、信息/衔接及文字身份；续话校验多一个上话输入。工具仅提供结构证据，实际画面、文字和因果仍必须人工/Agent 引证核对，不能保证或伪称自动理解剧情。
