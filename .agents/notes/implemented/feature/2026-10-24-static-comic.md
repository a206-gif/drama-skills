# Agent Note: 面向图文发布的一页多格静态漫画

Status: implemented

## Problem

创作者明确要将小说改编为一页多格、用于抖音和小红书图文发布的静态漫画。现有 `short-drama` 的分镜以时长、运镜和镜头起终状态为单位；“静态漫剧”仍是关键帧加配音剪成的视频。直接跳过视频生成不能解决漫画的阅读顺序、翻页揭示、对白气泡和静态页面交付。

检索了既有静帧剪辑、自包含技能与五文档决策；本变更新增独立媒介，不翻转既有视频项目的决定。

## Decision

- 新增独立安装的 `static-comic` skill，负责小说选段、按话/页/格改编、视觉一致性、逐格出图提示词与图文发布交接。不自动挑选仓库中的小说，不调用付费接口，不自动上传平台。
- 创作事实保留为少量 Markdown：简报、视觉设定、漫画分镜与可选发布文案；漫画分镜是每格画面、提示词与文字的唯一正文。排版 JSON 只保存坐标、格图路径和文字 ID，避免第二份对白真相。
- 增加确定性本地检查和页面拼排工具：检查结构与坐标只依赖标准库；有实际格图、显式字体和可选 Pillow 时导出静态 PNG/JPG。文字溢出不缩字，失败不留半批发布图，输出不覆盖原图。
- 以 1080×1440、从上到下同行从左到右、每页约 3–5 格作为可覆盖的创作起点，不宣称平台官方尺寸、图片数量或安全区；发布前在各平台实际预览中核对。
- 保留现有视频五文档、Dashboard 与生产闸门。已有原著分析与资产能力只按技能名可选调用；不把漫画文档冒充现有 `SHOT`/`IMG` 的生产输入。
- 加入合成示例、独立安装自测、结构与栅格行为回归；新增技能先明确排除 ClawHub 发布，不伪造上架状态或权限。

## Alternatives considered

- **把静态漫剧设为漫画输出**：现有关键帧和剪辑工具复用最多。但时间线、字幕与声音并不等于漫画页，因此不扩展这条路径。
- **让出图模型直接画整页和所有中文字**：初次出样步骤最少。但逐格修订、阅读顺序和文字准确性难保证，因此默认逐格无字出图后确定性排字，整页出图仅作为可选草稿。
- **改造现有分镜和项目配置，新增静态形态枚举**：统一路由、配置和生产接口最完整。但会改变已有时长、关键帧、Dashboard 和生产契约；本轮以独立技能及明确的图片交接边界控制影响面。

## Consequences

- 收益：从小说到可读漫画页有独立入口，手机阅读与中文字排版有具体做法；可以只用文本阶段，也可在获得图片后本地排成静态图片。
- 代价：新技能的漫画文档不进入现有视频 Dashboard；栅格渲染需要额外安装 Pillow 并提供可用、获授权的中文字体。规则与本地几何检查不证明图像质量、授权或平台审核通过。
