# 创作者文档模板

以下是起步结构，不必复制空文件。示例《送错的信》是合成书名和情节，不取自仓库小说，
不表示真实在架作品或已取得推广授权，不可直接对真实读者发布。正式项目替换为核实过的原著信息。
实际可检查分镜见 [两页首话](漫画分镜.md)和[三页续话](续话示例/漫画分镜.md)，对应[首话版式](page-layout.example.json)和[续话版式](续话示例/排版.json)。

## 创作简报.md

```markdown
# 创作简报

- 目标：推广原著，吸引读者搜索并阅读；不是完整漫画化或替代原著
- 原著准确书名：本合成示例用《送错的信》；正式作品须核实，不直接取文件名后缀
- 作者：本例未设置；正式作品记录已知作者，不猜测
- 原文与范围：创作者指定文件及章节/段落；本例仅为原创合成情节
- 授权与署名：核对是否包含本次推广改编；未知标待确认，不编造已授权
- 阅读平台/搜索词：平台未核实不点名；本例搜索词仅演示为“送错的信”
- 本轮范围：连载首话 CH001；先文本，不出图、不生成视频、不上传
- 连载关系：若做 CH002 必须接 CH001 的当前事件，不另找高光跳过；独立选段须创作者明确批准
- 图文硬要求：逐格准确表达必要事实，对白/旁白详细明确，身份/指代清楚；信息不足优先增格增页，不删关键过程
- 承接硬要求：先读上话实际末尾，进行中的事逐项继续、画清解决或在漫画中明确有依据地暂缓；交接以分镜话头为准
- 媒介：一页多格静态漫画，抖音/小红书图文；“第001话”仅是连载话号，不表示逐章画完全书，也不允许下话抛弃当前事件
- 页面与阅读：1080×1440，3:4，上到下、同行左到右（提议，创作者可改）
- 画风：平涂彩色漫画，清晰墨线，有限色阶（示例；服务悬疑卖点，不代替用户选择）
- 提示词语言：zh-CN（本模板选择，与创作者说明语言分开记录）
- 目标读者与主卖点：喜欢失踪谜团的读者；错投信件招来失踪者，来源为合成情节 1–7
- 本篇小兑现：打开门，确认来人和照片是同一个人
- 已展示：错投信、旧照片、门外人出现
- 留给原著的续读问题：失踪者为何回来、谁寄出了这封信；示例未创作答案，不承诺具体答案/章节
- 禁止剧透：失踪原因、写信人和核心结局
- 停止位置与理由：合成情节 7 开门认人之后；给到一个局部发现，再把追信动机带向原著
- 搜书呈现：本合成例已选画内PAGE-002 / TEXT-002-03，正文只在分镜维护；创作者选故事优先时可从源/布局一起迁画外文案
- 必须保留：错投信件、旧照片、失踪者出现的因果链，不为了推广编造新关系或反转
- 改编变化：写原著位置、保留/压缩/合并/前置/新增及影响；无则明确无
- 真实未决：正式原著名/授权、阅读入口、画风与实际格图等；不把候选标为可发布
```

## 视觉设定.md

```markdown
# 视觉设定

- 推广视觉职责：突出错投信、照片与门外人的对应；不用无关装饰抢走原著卖点
- 时代与地点：当代旧楼，绿色信箱在磨砂玻璃门内，门外是雨巷
- 画风锁：平涂彩色漫画，清晰墨线，有限色阶
- 光线：门内傍晚暖侧光；开门后才看见门外冷色雨光

## 人物：林岚
- 身份锚点：齐下颌黑发
- 造型锁：深蓝衬衫
- 状态：PAGE-001 左手持信封、右手取照片；PANEL-002-02 起左手并持信与照片、右手开门
- 参考图：未提供（不是已有图）；提供后登记真实路径、中文名、顺序、控制/不得控制范围

## 人物：陈默
- 身份锚点：短黑发、左眉尾浅疤；照片与本人同脸
- 造型锁：浅灰外套
- 状态：照片里干燥，PANEL-002-03 本人外套被雨淋湿
- 揭示边界：PANEL-002-03 前只见无身份特征的模糊影子

## 道具与文字区
- 信封锁：米黄色纸、破裂红蜡残印、封口在取信前就已打开；不在出图时拼可读文字，必要文字另排
- 照片锁：同一张黑白照片，陈默穿浅灰外套
- 地理锁：绿色信箱和磨砂门相对位置不变
- 末格图文：人物与照片为重心，字嵌自然低细节区域，必要叙述有来源；不固定留白字区，采用画内搜书才按计划留位置，不遮脸与证据
- 跨话状态：CH001 末物件仍在林岚左手；CH002 接着画问答/递出/接触/松手，最后陈默右手持信与照片，两人在门厅内继续追问；以当前分镜更新为准
```

## 漫画分镜.md 的必要结构

话头、正文与交接都在同一分镜里，不复制成另一份状态 JSON。完整可用格式见成对示例，
字段与命令见[排版格式](../references/layout-format.md)，信息深度见[信息与连续性](../references/information-and-continuity.md)。

- 首页前：本话编号、连载关系、上话编号、具体入口/出口状态；没有事件也明确写“承接事件：无”“待续事件：无”，不能省略。
- 每个上话待续事件：稳定 `EVT-*` ID、继续/解决/明确暂缓、当前真实格/文字落点、具体处理事实。
  未结事件保留待续，不伪标解决；独立篇依据必须真实，不拿它绕过承接。
- 每页：本页职责；每格：来源、读者应获信息、可见画面、具体前后衔接、完整无字提示词。
- 对白：说话人、对话对象、逐字台词；内心：人物归属；旁白：叙述身份与完整正文；拟声：明确声源。
  推广提示的叙述身份单列，不混成故事旁白。
- 不写“两人解释清楚了”代替实际对话；不以一句“次日”跳过必须交代的冲突、交接或关系转变。
- 先核对本格信息在实际图文中可见，再核对上下话事件；只有模板/文字或结构通过不等于成品。

## 发布文案.md

```markdown
# 第 1 篇推文图文交接

- 目标：让读者带着“失踪者为何回来”的疑问搜索原著，不以完整讲完剧情为目标
- 原著准确书名：本合成示例用《送错的信》；正式发布需真实作品信息
- 作者：未设置，不编造
- 搜索词/阅读平台：本例词“送错的信”仅演示；平台未核实不点名
- 本篇标题候选：门外的人（不是原著书名）
- 简介：一封投错的信，把失踪三年的人带回了门口。后续沿同一原著搜索信息承接，不补泄漏保留答案。
- 标签候选：小说推文、悬疑漫画（按内容与平台有效要求调整，不保证推荐）
- 搜书信息：按已选画内/画外方案交付；本例画内PAGE-002 / TEXT-002-03须与源一致，若迁画外需同步源/布局并检查文案书名
- 已给到的小兑现：门外人与照片对应
- 信息与承接自检：逐格图文/说话关系要明确；续话注明实际核对的上话及所有待续处理，不能用搜书提示代替事件交代
- 本话出口/未结：制作交接以当前分镜话头为准；本合成首话尚未归还信件、未解释失踪，后续不得无交代清空
- 保留与停点：不解释失踪/写信原因，停在开门认人后；不承诺未核实的答案或章节
- 封面：PAGE-001；另做封面不得虚构剧情或泄漏保留答案
- 上传顺序：PAGE-001.png → PAGE-002.png
- 原著/推广改编/素材/字体授权与署名：待提供或核验
- 推广/AI 标识、引导方式与内容提示：按当次有效要求核验，不编造免费/完结等声明
- 抖音当次预览：待检查封面/数量/格式/清晰度，以及搜书引导和推广要求
- 小红书当次预览：同样待核验，不假设两边规则相同
- 状态：纯合成文本示例；未出图、未检索、未上传，不是真实可发布推广稿
```

## 排字策略约定

示例旧JSON不配置lettering时保留labelled兼容。创作者选择画内贴字时，显式embedded，姓名/类型只作制作元数据；主角专属字体用于全部正文，气泡半透明但字不透明，字色/框形/位置协同。具体字段见本skill排版格式，不为文字单独开白带。
