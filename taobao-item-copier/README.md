# 淘宝商品搬运台

把别人店铺里的商品，采集到本地 → 批量清洗改写 → 发布到你自己店铺。
本地单机运行，数据不出你的电脑。**只用你自己的淘宝登录态，默认不需要开放平台 appkey。**

```
采集端                     本地服务                      发布端（两条路，二选一）
浏览器扩展  ──HTTP──▶  商品库 / 清洗改写 / 图片落地  ─┬─▶ ① 网页自动填表：扩展打开发布页替你填，你点提交
（你的登录态）          （127.0.0.1，数据全在本机）    └─▶ ② 官方 TOP API：taobao.item.add 全自动（需 appkey）
```

## 先说清楚三件事

**1. 为什么采集要用浏览器扩展，不能后端直接爬？**
淘宝商品页和 mtop 接口都要登录态，mtop 的签名 `sign = md5(token&t&appKey&data)` 里那个 `token`
取自 `.taobao.com` 域下的 `_m_h5_tk` cookie。本地服务的页面跨域读不到这个 cookie，就签不出名。
扩展跑在你已登录的浏览器里，天然有 cookie、能签名、还能直接读页面 DOM——这是唯一稳定路径。

**2. 发布有两条路，先省事就用第一条。**

- **① 网页自动填表（默认，省事）** —— 就是你在别处见到的"只登录就能一键发布"。
  在商品库点「🚀 网页发布」，扩展用你的登录态打开淘宝发布页，自动把标题、价格、库存、详情、
  主图填进去，你核对后**自己点「提交宝贝」**。不需要申请 appkey、不需要授权。
  代价你要知道：发布页一改版就可能某些字段填不进（工具会如实标出来让你手动补），
  类目、关键属性、SKU 矩阵这类复杂控件本就需要你手动确认。
- **② 官方 TOP API（可选，最稳）** —— `taobao.item.add` 全自动批量发布，不受页面改版影响。
  代价是要去开放平台建应用、申请权限、给店铺授权（见下文「附：官方 API 发布」）。
  适合量大、要长期稳定跑的场景。

**3. 合规提醒（重要）**
他人商品的**标题文案、主图、详情图受著作权保护**，直接照搬上架有被投诉、被扣分、被下架的风险。
本工具的定位是**铺货/分销/搬自己有权使用的商品**的效率工具，已经内置了标题改写、品牌替换、
详情清洗这些"二次创作"能力。请只搬运你有权使用的商品（如分销授权、自有货源、1688 一件代发等），
并遵守《淘宝平台服务协议》。滥用导致的后果由使用者承担。

## 安装运行

需要 Node.js 18+（自带 `fetch` 和 `--test`）。

```bash
cd taobao-item-copier
npm install
npm run seed        # 可选：写入演示数据，不连淘宝也能先看界面
npm start           # 打开 http://127.0.0.1:8787
```

## 三种采集方式（按推荐度排序）

### 方式 A：浏览器扩展（推荐，能"给个店铺链接抓全部宝贝"）

1. 打开 Chrome → `chrome://extensions` → 右上角开启「开发者模式」
2. 点「加载已解压的扩展程序」→ 选择本项目的 `extension/` 目录
3. 在淘宝/天猫页面点扩展图标 → 填本地服务地址（默认 `http://127.0.0.1:8787`）
   和采集口令（控制台「设置」页可复制）→ 保存并测试连接
4. 之后：
   - **商品页**：右下角出现 📥 浮标，点「采集」入库，点「补全详情」连 SKU 一起抓
   - **店铺页**：点「采本页」抓当前页所有宝贝，点「采整店」下发整店采集任务
   - **控制台「采集导入」页**：填店铺链接 → 开始采集整店，实时看进度

整店枚举有两条策略自动兜底：先走 mtop 店铺宝贝搜索接口（快、字段全），
失败退回 DOM 解析店铺「所有宝贝」页（慢但最耐改版）。

> **mtop 接口名会变。** 如果整店采集报接口错误：在店铺「所有宝贝」页按 F12 → Network →
> 过滤 `mtop` → 翻一页 → 找到返回宝贝列表的那条请求，把 URL 里的 `api`、`v`、`data`
> 抄进扩展弹窗的「高级：mtop 接口配置」即可，不用改代码。

### 方式 B：粘贴页面源码（不装扩展也能用）

在商品页 `Ctrl+A` → `Ctrl+C`，或 `Ctrl+S` 存成「网页，仅 HTML」，
把内容贴进控制台「采集导入」页的粘贴框。店铺页 HTML 也认（自动提取里面所有宝贝链接）。
支持自动识别 HTML / JSON / CSV。

### 方式 C：CSV 批量导入

已经整理好的表格，表头支持中英文：`标题,价格,库存,主图,链接,类目`。

## 发布方式 ①：网页自动填表（默认，只登录就行）

这是最省事的路子，**不需要开放平台 appkey、不需要授权**，只用你自己已登录的淘宝身份。

前提：已按下面「安装运行」装好扩展、本地服务在跑、淘宝处于登录状态（顶栏显示「扩展在线 ✓」）。

步骤：

1. 在「商品库」里找到要发布的商品（建议先在「批量改写」页把标题、价格、品牌改写好）
2. 点该商品下的 **🚀 网页发布**
3. 扩展自动打开淘宝发布页，并**在新标签页里自动填表**：标题、一口价、库存、详情、主图（图片会先下载好再注入上传框）
4. 页面右上角弹出「搬运台 · 自动填表」面板，如实列出：
   - ✅ **已自动填好** 的字段
   - ⚠️ **需要你手动完成** 的项（类目、关键属性、SKU 矩阵、物流、以及最后的提交）
5. 你按面板提示**先选宝贝类目**（选完类目，表单才完整加载，标题等字段才会被填入），再补齐属性/SKU
6. 核对无误后，**你自己点「提交宝贝」** —— 工具不会替你提交

> 如果某个字段没填进去：多半是淘宝发布页改版了。手动补一下即可，其余功能不受影响。
> 发布页地址若变了，可在扩展弹窗的高级选项里改 `publishUrl`。

**这条路的能力边界（诚实告知）：**

| 能自动 | 需手动 |
| --- | --- |
| 标题、一口价、库存、商家编码 | 宝贝类目（异步树控件，自动选易错） |
| 图文详情（HTML） | 关键属性 / 品牌（选完类目才出现） |
| 主图（下载后注入上传框） | SKU 规格矩阵（颜色×尺码的价格库存） |
| | 物流、运费模板、所在地 |
| | **最后的「提交宝贝」** |

## 发布方式 ②：官方 TOP API（可选，最稳，需凭据）

量大、要长期无人值守地批量发布时用这条。不受页面改版影响，但要走开放平台。

### 第一步：建应用、拿凭据

1. 打开 [open.taobao.com](https://open.taobao.com)，用**企业支付宝实名**的账号注册开发者
2. 控制台 → 创建应用 → 选「**自用型**」
3. 拿到 **AppKey** 和 **AppSecret**
4. 「接口管理」里申请商品发布权限包，至少要这些接口：

| 接口 | 作用 |
| --- | --- |
| `taobao.item.add` | 创建商品（核心） |
| `taobao.item.update` | 改详情、补字段 |
| `taobao.item.img.upload` | 传第 2~5 张主图 |
| `taobao.item.propimg.upload` | 传颜色分类的属性图 |
| `taobao.itemcats.get` | 查类目树 |
| `taobao.itemprops.get` | 查类目必填属性和销售属性 |
| `taobao.picture.upload` | 传图片空间（可选） |
| `taobao.user.seller.get` | 验证授权到的是哪家店 |
| `taobao.item.update.listing` | 上架（可选） |

### 第二步：在控制台「设置」页填凭据 + 授权

- 填 AppKey / AppSecret → 保存 → 点「连通性自检」
  自检会依次验证：凭据完整性 → 签名与网关（`taobao.time.get`，不需要 session）→ 店铺授权
- 点「授权登录」，用**卖家账号**登录并同意授权，token 自动写回本地
- 如果你的应用回调地址登记的是线上域名、对不上本机，就手动粘贴 access_token

### 第三步：查类目和必填属性

到「类目属性」页，一层层点到**叶子类目**（非叶子类目不能发布商品），
点「用这个类目」会自动填进发布页。右侧列出该类目的**必填关键属性**和**销售属性**——
发布失败十有八九是这里没填全。

### 第四步：批量发布

在「商品库」勾选商品 → 「发布」页设置类目、上架方式、运费、所在地 → 开始发布。

发布链路（每步都记日志、失败即停并保留已建商品 id）：

```
① 定类目 → ② 查必填属性 → ③ 传图片 → ④ taobao.item.add
→ ⑤ 补主图 → ⑥ 补属性图 → ⑦ 补详情 → ⑧ （可选）上架
```

**强烈建议**：
- 先用「**试运行**」——只校验参数、不调真实接口，把类目/属性/图片问题提前暴露
- 上架方式选「**存入仓库**」而不是「立即上架」，人工核对无误再上
- 第一次先发布 1~2 个商品验证全链路，再批量

## 批量清洗改写（搬运的核心价值）

「批量改写」页可以一次处理几百条，**先「预览效果」看清前后对比，再「应用改写」落库**：

| 项 | 能做什么 |
| --- | --- |
| 标题 | 加前后缀、删品牌词、删【】内容、关键词替换（支持正则）、同类商品加不同修饰词防同质化 |
| 价格 | 倍率、加价、尾数（`.9` 结尾）、最低/最高夹逼；SKU 价格整体改写并保留差价结构 |
| 库存 | 统一设一个值（同步作用到所有 SKU） |
| 图片 | 去掉 CDN 尺寸后缀取原图、限制主图数量 |
| 属性 | 品牌替换成自己的（**必须做**，否则会被判侵权） |
| 详情 | 去掉脚本/外链/二维码/店招/客服浮层，协议补全 https，插入自定义头尾 HTML |

标题严格按**字节**裁剪（淘宝上限 60 字节 = 30 个汉字），不会把多字节字符切成乱码。

## 导出上架素材包

就算 API 权限还没批下来，采集 + 清洗的成果也能落地：
「商品库」勾选 → 「导出素材包」，得到一个 zip：

```
items/      每个商品一份 JSON（可重新导入本工具）
images/     按商品分目录，1.jpg 是主图封面，顺序即主图顺序，可直接拖进发布页
desc/       商品详情 HTML，可粘贴进详情编辑器
商品总表.csv  UTF-8 BOM，Excel 直接打开不乱码
README.txt
```

## 测试

```bash
npm test
```

76 个用例，覆盖四块最容易出错的地方：
- **TOP 签名**：与 Node crypto 逐字节对齐，含中文、hmac、空值过滤
- **扩展 MD5**：标准测试向量 + 与 Node crypto 的模糊测试（mtop 签名的地基）
- **解析**：商品页 HTML、mtop JSON 启发式扫描、skuBase+skuCore 拼装、店铺页、CSV
- **端到端**：起真实 HTTP 服务，走完采集→去重→改写→试运行发布→导出，含采集口令、CORS、SSE

## 安全设计

- 服务**只监听 127.0.0.1**，不对外暴露（里面存着 appsecret 和 session）
- 采集入口有**口令校验**，防止本机其他网页往你的商品库塞数据
- 设置接口返回的 secret/session **只给掩码**，前端拿不到明文
- 图片下载**只允许淘系 CDN 域名**，避免本地服务被当 SSRF 跳板
- `data/` 和 `.env` 都在 gitignore 里，凭据不会误提交

## 常见问题

**采集整店报 mtop 接口错误？**
接口名会变，按上面「方式 A」的提示抓一下当前接口填进扩展选项。或改用 DOM 方式。

**发布报 `isv.invalid-parameter` / 缺属性？**
到「类目属性」页查该类目的必填关键属性，在商品编辑页补齐。错误里会带 `hint` 说明。

**发布报 `isv.session-expired`？**
access_token 过期了，到「设置」页重新授权。

**图片传不上去？**
外链直传（`pic_path`）要求图片公网可访问且是淘宝认可的域名。改用「先下载再以字节上传」
（发布页的「图片方式」选 `local`），或先跑一次「下载图片到本地」。

**能不能不用扩展？**
可以，用「方式 B」粘贴页面源码，或「方式 C」CSV 导入。但整店批量枚举需要扩展。
