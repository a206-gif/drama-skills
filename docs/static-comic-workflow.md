# 小说推文 → 一页多格静态漫画

**目标是推广原著，让读者看完漫画后想搜索并阅读原著，不是把小说完整漫画化。**
形式是用于抖音、小红书图文的可翻阅漫画图片，不是动态视频、配音切图或整条长图。
入口为 [`static-comic`](../skills/static-comic/SKILL.md)，可独立安装；不改变视频技能与 Dashboard。

**表达与承接是硬要求：画面准确，台词旁白详细明确，上一话正在讲的事下一话绝不无交代跳过。**
悬念可以保留，必要因果不能省掉；不能为了推文短快、页数或搜书引导让读者看不懂。

## 第一轮怎么说

指定你有权推广改编的小说、可用范围和已知作品信息，例如：

```text
用 $static-comic 为我获准推广改编的 输入/小说.txt 做第 1 篇漫画推文，
一页多格，用于抖音和小红书图文。所有创作都服务原著推广，让读者搜索并阅读原著，
不是完整漫画化。从我指定的可用范围选最能代表原著吸引力的一段，
说明主卖点及来源、小兑现、剧透边界、停止位置与续读理由。
画面准确表达信息，人物对白和旁白详细明确，必要过程不能省略；篇幅不够就增格增页。
连载各话必须承接，续话先读上一话实际结尾，正在讲的事情不能莫名消失。
核实准确书名，末页加独立搜书文字；作者/阅读平台不确定就不要编造。
先做简报、视觉设定、分页分镜、逐格无字提示词和发布文案，止步于文本，不生成媒体。
```

选段以用户提供和实际读过的范围为准，不保证第一章最好，也不把章节数当推文数量。
初篇可以选择原著中段；连载一旦开始，续话不能因为另一个高光更吸引人就丢掉当前事件。
有多部小说必须点名，不能因仓库有原文就自动选书或认定有推广改编权利。

## 三条不可省略的验收标准

### 1. 画面确实传达信息

每格写清“读者应知道什么”，再写场景、人物、动作、视线、关键道具和构图。
不能只给“一个震惊的脸”，却不让读者知道她看见什么、为什么震惊。
实际图片和排入文字要逐项满足本格的信息；提示词写对、图片文件存在，都不等于画对。
人物拿错东西、左右站位混乱、关键动作没画或证据被文字遮住，先修复再交付。

### 2. 对白和旁白详细明确

- 对白：写完整实际台词，明确谁对谁说、谁听得到，不拿“两人解释清楚了”代替内容。
- 内心：明确属于谁，不把某人的猜测变成所有人都知道的事实。
- 旁白：明确第三人称、角色回忆等叙述身份，必要的时间、地点、关系与原因讲到足够理解。
- 搜书提示：单列为推广提示，不伪装成角色说话，也不混成故事叙述。

先约定画面辨识策略，不强制加姓名标签。embedded是画内贴字：角色完整正文用约定专属字体与字色，配气泡/内心样式、位置/尾巴，源中的姓名/类型仍完整但不画出来。labelled保留旧标签模式供选择；旧JSON未配置仍兼容该模式。
通过`lettering.mode: embedded`与`bubble_opacity`启用轻透底，字本身不透明；`--speaker-font`作用于该角色全部对白/内心，非只名签。自然断行可用源字符`breaks`，不复制或缩删正文。
必要的原著叙述按来源处理，小说有叙述不等于漫画每格必须加解说。人物已有内心可承担认知，场景/动作已画明就不复述；不能新增人物不该知道的信息。

“详细”不是凑字数或挤满气泡，而是重要信息不漏、该解释的说到位。
不设通用对白字数或旁白越少越好的门槛。放不下就增格、增页、重排，不能缩字或删必要解释。

### 3. 每话都接住上话的事

先读上一话当前分镜和实际末尾，再写下一话，不只凭记忆或梗概。
核对时间地点、正在进行的动作/对话/追问、人物认知与关系、物件持有和伤势等状态。

上一话每个待续事件，本话都必须：

| 处理 | 漫画里需要什么 | 下一话交接 |
|---|---|---|
| 继续 | 实际接着推进同一动作、对话或追问 | 仍列为未结 |
| 解决 | 有足够清楚的过程、结果与后果 | 不再列为未结 |
| 明确暂缓 | 画内说明有依据的原因、还欠什么、接下来怎么做 | 仍列为未结，不能悄悄遗忘 |

**不允许**：上话还在递信，下话信已经在别人手里；上话还在质问身份，下话双方突然信任合作，却没有交代。
**允许**：大谜团保留，但眼前行动有进展、读者知道问题没解以及人物下一步在做什么。
转场、时间跳跃或倒叙须在漫画中清楚可辨，不能只在制作备注里说明，更不能借此跳过关键冲突。
独立选段需要创作者明确批准；不得把原本续话改称“独立篇”清空未结。

## 推广目标怎样改变做法

| 环节 | 不以此为目标 | 改为服务原著阅读 |
|---|---|---|
| 选段 | 从第一章起顺序画完 | 初篇选真实卖点；续话先接已有事件再推进 |
| 首张 | 无关漂亮图、空泛标题 | 有来源且读者看得懂的冲突、关系或反差 |
| 中间 | 流水账，或只吊胃口 | 细致的必要理解、明确对白旁白与真实体验 |
| 停点 | 泄露谜底和结局，或删过程假悬念 | 给局部兑现，再保留具体原著续读问题 |
| 搜书 | 只写“未完待续” | 画内准确原著名，必要时加已核实作者/平台 |
| 验收 | 只问好不好看、能否拉搜 | 还问是否准确讲清楚、与上话连贯、是否误导 |

不是每篇都卡在爽点前，更不能捏造原著没有的关系、反转或奖励来拉搜。
初篇试少量页是建议，不是牺牲细致内容的配额；不必画完全书才可以推广。
本轮推广可以保留问题并停在原著阅读入口；若以后制作续话，仍从记录的出口和未结状态接着走。

## 文件与制作链

```text
确认原著、可用范围、推广目标、准确作品身份
→ 简报：真实卖点/来源、小兑现、保留问题、停止位置和搜索词
→ 续话先读上话结尾：入口状态与全部待续事件
→ 视觉设定：人物/服装/场景/道具及跨话状态
→ 漫画分镜：话头交接 → 页 → 格 → 文字
→ 每格：来源、信息、可见画面、具体衔接、完整无字提示词
→ 文字：逐字台词、明确说话人与对话对象、旁白叙述身份
→ 实际格图 → 准确排字 → 逐格信息与逐事件承接自检
→ 编号 PNG/JPG + 发布文案、上传顺序与待办
```

所有故事正文和最小事件交接都在《漫画分镜.md》，不另建第二份连续性数据库。
话头记录本话号、连载关系、上话号、入口/出口状态；稳定事件 ID 引用真实格/文字，交代每件未结的去向。
JSON 只存几何、图片路径、文字 ID 与字号，不复制对白、提示词或交接。

[两页首话](../skills/static-comic/assets/漫画分镜.md)与[三页续话](../skills/static-comic/assets/续话示例/漫画分镜.md)
演示“门口索信 → 当面问答 → 递出 → 接触 → 松手归还 → 避雨后继续追问失踪”。
书名《送错的信》和全部情节均为原创合成示例，无真实格图、不表示在架作品，不可冒充真实可发布推文。

## 书名与搜书提示也要准确排字

默认逐格出无字图，再后期准确排字，避免出图模型拼错中文和书名。
推广模式先选画内/画外搜书策略；末页提示是可选默认，用户要求故事优先可放发布文案，不以新增广告格挡画。采用画内时仍从真源TEXT取字，位置不挡关键内容。
简介、封面、正文和发布文案对齐准确原著名/搜索词；不能只在简介里提书名就声称画内提示已完成。

书名、作者、平台、免费/完结等未核实不编造；书名未确定可先做候选分镜，不能把搜书卡标为可发布。
完整推广交接需要发布文案；仅文本/仅拼页请求不自动扩范围，未完成项诚实标待办。

## 本地检查、拼页与导出

```bash
# Python 3.9+，文本/版式检查不需第三方依赖
python3 skills/static-comic/scripts/comic_tool.py check 项目/第001话/排版.json

# 续话必须显式提供实际上话的 Markdown；不能只填话号
python3 skills/static-comic/scripts/comic_tool.py check 项目/第002话/排版.json \
  --previous 项目/第001话/漫画分镜.md

# 图齐后可给 check 加 --media；导出才需 Pillow 与可用中文字体
python3 -m pip install "Pillow>=10.4,<12"
python3 skills/static-comic/scripts/comic_tool.py render 项目/第002话/排版.json \
  --previous 项目/第001话/漫画分镜.md \
  --font <中文字体.ttf或otf> --out 项目/第002话/发布-v1 --format png
```

工具拒绝缺上话、跳话、漏掉/改名未承接事件、无实际落点、继续/暂缓却被清空、已解决仍待续等结构矛盾。
它只核对相邻一对的声明和引用，不能证明事件真的解决、延期有理或画面/台词确实讲清。
这些语义义务仍需对照原著、当前分镜和实际图片逐项自检；失败先修复，不能把结构通过冒充内容通过。

导出会测量文字；溢出/缺字拒绝，不缩字删词。任一页失败不留半批图，修改后用新目录，不覆盖源图或旧发布版。
支持矩形行带；异形格、出框、复杂竖排使用外部工具。不自动做 PDF/CBZ、视频或平台上传。
格式详见[排版格式](../skills/static-comic/references/layout-format.md)，内容标准见[信息与连续性](../skills/static-comic/references/information-and-continuity.md)。

## 手机图文建议与发布边界

- 3:4、1080×1440、统一页尺寸；每页约 3–5 格只是起点，信息需要时增格增页。
- 模板边距 48px、字号 40px；包括对白旁白与书名，在手机实际大小看可读性和信息完整性。
- 静态 RGB PNG/JPG、按页编号；封面/正文顺序与作品定位写入发布文案。

**这些不是平台官方尺寸、数量、字号或安全区规定。** 分别核验当次上传预览、引导方式、推广与 AI 标识。
若当次数量限制容不下，先核实规则并找合理拆话点，不无交代删掉事件。
不保证流量/转化，不以暗号、错字或虚假说明规避规则。模板、自检或几何通过都不等于平台发布成功。

## 下一步需要的素材

实际改编时提供：指定小说与可用原文范围、准确书名/已知作者、推广改编权限、画风或可用参考图；
点名原著阅读平台时给确认信息。续话另给实际上话分镜/已接受末页；已在项目中的直接读取，不重复询问。
本轮不会自动选仓库小说、付费出图、登录或上传平台；没有真实格图只交文本，不称漫画成品。

## 弹性多镜与局部实图试排

普通段落默认一页多镜，单镜独幅通常用于重要转折；格数、大小、横竖与组合跟随剧情、阅读顺序和完整文字，不固定等大模板，也不由单格素材张数决定发布页数。

版面不足先调格/页或用格内`image_rect`分离图片区与文字区，不缩字/省必要过程。整话缺图时可用`comic_tool.py preview 排版.json --page PAGE-... --font 字体 --out 新目录`试排已齐图页；续话仍须`--previous`。结果是`preview_rendered`局部试排，不是全话媒体/平台验收。

每轮交付给可执行下一步选项；本轮可迁移优化同轮回写[skill制作技巧](../skills/static-comic/references/production-learning.md)，不只留项目存档，标明适用范围/实测或待验证。
